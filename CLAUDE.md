Phase 1 (structural conversion — pages moved to `src/*.njk` + `src/_includes/base.njk`, shared header/footer/script now in `src/_includes/site-{header,footer,script}.njk`, nav links in `src/_data/site.json`, build via `npm run build` → `_site/`, Netlify runs the build; **no visual or content change**) is done pending review. `src/site-chrome.njk` → `/partials/site-chrome.html` is a rendered, marker-delimited export of the header/footer/script that the **dbc-resources** repo fetches at build time (replacing its old fetch of this repo's `index.html`). The static-HTML notes below — including the `sync-partials.py` / `HEADER-START` marker workflow — are stale and will be rewritten after Phase 2 (Decap CMS layer). See the migration plan in the active chat session.

- This is a static HTML/CSS/JS site for Design by Cristina, no build step or framework in this repo.
- **Shared header & footer are auto-synced from `index.html`.** The nav (`class="navlinks"`) and the `<footer>` block are duplicated across `index.html`, `portfolio.html`, and `pricing.html`, but `index.html` is the single source of truth. The markup between `<!-- HEADER-START -->`/`<!-- HEADER-END -->` and between `<!-- FOOTER-START -->`/`<!-- FOOTER-END -->` in `index.html` is copied verbatim into the same marked regions of the other two files by `tools/sync-partials.py`. **Only edit the header/footer in `index.html`**, then run `python3 tools/sync-partials.py` (idempotent, Python 3 stdlib only, no dependencies; `--check` reports drift without writing). The synced regions in `portfolio.html`/`pricing.html` carry an `<!-- AUTO-SYNCED FROM index.html — edit there, not here -->` line; hand-edits there are overwritten on the next sync. Current canonical `footlinks`: Clarafide (`/#app`), Solutions (`/#solutions`), Services (`/#services`), Pricing (`/pricing.html`), Portfolio (`/portfolio.html`), Resources (`/resources/`), Contact (`/#contact`). (The flagship product was renamed from "Forms App" to "Clarafide" on 2026-09-05; the `/#app` anchor and `id="app"` section id were left unchanged.)
- **The `HEADER-START` / `HEADER-END` / `FOOTER-START` / `FOOTER-END` marker comments are load-bearing** for that sync. Do not remove them, move them, or treat them as stray comments. Each must appear exactly once per file; `tools/sync-partials.py` errors out and writes nothing if any marker is missing, duplicated, or out of order.
- **A `pre-commit` hook enforces the sync.** `.githooks/pre-commit` runs `tools/sync-partials.py` before every commit and aborts the commit if it produced changes to `portfolio.html`/`pricing.html` that were not staged, telling the user to review and re-stage. It is enabled **per clone** with a one-time command — `git config core.hooksPath .githooks` — because `git clone` does not install hooks. Bypass in an emergency with `git commit --no-verify`. If a nav/footer change is committed via a Claude Code session, still run `python3 tools/sync-partials.py` and stage all three files as part of the same commit.
- Anchor link style should be consistent across all three files: use the `/#section` format (e.g. `/#contact`), not `#section`.
- This repo is on GitHub as `skinesti/dbc-site-live` (private). To deploy: commit locally, then push `main` to GitHub **from a real Terminal window, not from within a Claude Code chat session**. Netlify auto-deploys from its GitHub connection on every push to `main`. The old zip-and-drag Netlify workflow was fully replaced on 2026-09-03; the historical `dbc-site-XX.zip` archives were moved to `../dbc-site-live-zip-archive/`, outside the repo.
- Brand colors and fonts are defined in `style.css` as CSS variables (`--teal`, `--clay`, `--ink`, etc.), along with `--serif` (Playfair Display) and `--sans` (Jost).
- `style.css` in this repo is the single source of truth for site styling. The separate dbc-resources site (dbc-resources.netlify.app, proxied here via `/resources/*` in `_redirects`) has a fetch-style build step in its own `package.json` that pulls `style.css` from this repo's raw GitHub URL before every build, so any CSS change here propagates to dbc-resources automatically on its next deploy — no manual copy needed. Proxied `/resources/*` pages also load root-relative `/style.css`, `/images/...`, etc. from *this* site.
- Always flag any inconsistency you notice across the three HTML files rather than silently skipping it.
- Required final step: after any changes to deployable content (`index.html`, `portfolio.html`, `pricing.html`, `style.css`, or the `images` folder) are made and confirmed, stage and commit them locally with a descriptive message. Do not push from within a Claude Code chat session — the user pushes `main` from a real Terminal window, and that push is what triggers the Netlify auto-deploy. `CLAUDE.md` and `PROJECT-NOTES.md` are documentation, not deployable content — edits to them alone do not trigger this step.
